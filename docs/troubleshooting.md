# 常见问题

## 修改失败，出现 `retcode=1200`

这个编号说明客户端执行失败，单凭 AstrBot 里的编号无法确定具体原因。如果 `message` 和 `wording` 也为空，需要查看同一时间的 QQ 客户端日志。

1. 在出问题的群里用 AstrBot 管理员账号执行 `/名片检查`，确认连接名称、机器人 QQ 号、群号和成员信息能否读出。
2. 用 `/名片预览 午睡中` 检查最终文本长度。把基础名字、模板和后缀暂时设短，排除长度或特殊字符问题。
3. 等待失败冷却结束，再尝试一次。不要让模型连续调用改名工具。
4. 查看 LLOneBot、llbot 或 SnowLuma 同一时间的日志，检查成员 UID 查询、QQ 接口返回和账号在线状态。必要时先验证该 QQ 账号能否手动修改自己的群名片。

默认每轮最多尝试 3 次，重试间隔为 2 秒、4 秒。明确的参数、权限或接口不支持错误会停止重复写入。每轮失败后暂停更新 300 秒，自动模式与工具模式共用这段冷却。

插件不能绕过 QQ 的权限、内容限制或频率限制。不要仅因为 `1200` 就给机器人管理员权限：修改自己的名片是否受限应以实际群设置与客户端返回为准。

## 重启后在线正常，但改名片持续失败

在 llbot + PMHQ 环境中，如果机器人在线、成员信息正常，却在多个群持续出现无说明的 `1200`，还需要检查客户端是否认错了机器人内部身份。UID 是 QQ 内部使用的用户标识，与常见的数字 QQ 号不同；插件提交的是数字 QQ 号，转换由 llbot 完成。

维护客户端时可按以下顺序核对：

1. 确认 `get_login_info` 返回的 QQ 号就是机器人账号。
2. 从实际群成员记录取得这个 QQ 号对应的 UID，与 PMHQ `/health` 和 llbot 使用的自身 UID 比较。
3. 如果不一致，向 QQ 查询该 UID 对应的 QQ 号，确认身份错误后再修复客户端。不能只因字符串格式正确就信任它，也不能把失败返回强制改成成功。
4. 修复后用标准 `set_group_card` 修改自己的名片，再通过 `get_group_member_info`、`no_cache=true` 确认实际生效。

已确认的一次故障中，错误 UID 导致 QQ 返回 `1013`；同群、同文本换成核实后的自身 UID，返回 `0` 并恢复正常。该实例在 llbot 登录流程中增加了身份校验：先向 QQ 核对 PMHQ 提供的 UID；若不匹配，再核验当前账号原登录记录中的 UID；无法核实时不使用该身份。它是客户端侧修补，不包含在插件中，插件更新不会自动修复 PMHQ 的身份识别。

重启客户端有时会重新取得正确身份，但仍应核对结果。客户端本地补丁可能被升级覆盖，升级后需要再次检查；保存日志时不要公开令牌、登录记录或完整账号配置。

## 接口返回成功，QQ 里却没变

默认会通过 `get_group_member_info` 回读。回读仍为旧值时会短暂等待后再次读取，再决定是否重试写入；最终不一致会报告失败。

如果写入接口成功但成员回读接口不可用，插件只报告“接口已接受、尚未确认”，不会声称已经核实成功。检查客户端是否实现成员信息接口、是否缓存未刷新，以及是否有其他插件同时改名。

## 没有自动更新

- `auto_update` 在机器人回复群消息时检查间隔，不会在安静的群里自行醒来。
- `tool_reminder` 默认在有模型请求时提醒，需要模型支持工具调用，且人格中启用了 `set_dynamic_group_card`。
- 希望安静时更新，请使用 `active_agent_cron`；先在目标群聊一次，并检查 AstrBot 定时任务列表和模型配置。
- 检查插件开关、群/会话黑名单、更新冷却，以及日志里的 cron 注册失败原因。

## Linux 云服务器上的时间不对

时间与日程使用 AstrBot 运行环境的本地时区。检查宿主机以及 Docker 容器内部时间；需要北京时间时将运行环境时区设为 `Asia/Shanghai`。主动 cron 还应核对 AstrBot 调度器的时区。插件不会修改系统时间或时区。

## 改名后回复慢

提醒模式通常先请求模型选择名片工具，工具执行完后再请求模型继续回复。后续模型请求或其他工具调用也可能耗时。打开 `common.debug_log` 后可用以下日志定位：

| 日志字段 | 对应阶段 |
| --- | --- |
| `reminder reached tool` / `wait_seconds` | 提醒注入到模型开始调用名片工具 |
| `set_group_card` / `attempts` / `verified` | 改名片接口的尝试次数与回读结果 |
| `tool_to_response_seconds` | 名片工具完成到模型返回后续回复 |
| `reminder agent finished` | 整轮 Agent 结束 |

调试日志可能包含生成的名片、工具名称和提醒内容。反馈问题时只提供相关片段，去掉不希望公开的聊天内容与账号标识。

## 手动后缀到期后还显示着

有效期控制的是插件下次渲染时是否采用该后缀。到期本身不会触发一个改名任务；需要后续更新才能改变 QQ 上已显示的名片。可以让机器人清除手动后缀，或设置主动任务。
